# 投资分析系统使用指南

## 系统概述

这是一个完整的 **A 股/美股基本面分析流水线**。从输入一个股票代码开始，系统自动完成以下全流程：

```
股票代码
    │
    ▼
┌─ 第1层：数据采集 ──────────────────────────────────┐
│  6个数据源 → 5年财报 + 行情 + 分红 + 内幕 + 宏观    │
└─────────────────────────────────────────────────────┘
    │
    ▼
┌─ 第2层：8个分析脚本 ────────────────────────────────┐
│  ARV计算 / CapEx拆分 / ROIC-WACC / 利润率分解       │
│  资本配置审计 / 内部人检查 / 会计异常检测 / 压力测试  │
└─────────────────────────────────────────────────────┘
    │
    ▼
┌─ 第2.5层：交叉校验（安全阀）───────────────────────┐
│  8项检查：现金完整性 / 币种 / ROIC / 利润质量 / 债务 │
└─────────────────────────────────────────────────────┘
    │
    ▼
┌─ 第3层：AI生成4份独立报告 ─────────────────────────┐
│  投资备忘录(9板块) + 思考链 + 批判性审视 + 巴菲特视角 │
└─────────────────────────────────────────────────────┘
    │
    ▼
┌─ 第4层：Notion 上传 ──────────────────────────────┐
│  子页面 + 版本管理 + 批次分隔标记                     │
└─────────────────────────────────────────────────────┘
```

---

## 一句话用法

对 AI 说：**"分析一下 [股票代码] 的投资价值"**

例如：
- `分析一下 002327.SZ 的投资价值` → 富安娜
- `分析一下 XNET 的投资价值` → 迅雷
- `分析一下 DUOL 的投资价值` → Duolingo

## 第1层：数据采集（做了什么）

由 `financial-data-acquisition` skill 负责。采集器 `fetch_financials.py` 一次性从 6 个数据源拉取数据，合并为一个 JSON：

### 6 个数据源详解

| 数据源 | 获取什么 | 为什么需要 |
|--------|---------|-----------|
| **yfinance** | 5年利润表/资产负债表/现金流量表 + 实时股价/市值/PE/PB/Beta | **主力数据源**。所有财务分析的基础 |
| **Baostock** | A股分红（每股¥、除权日）+ 最新季度利润表 + 行业分类 | yfinance对A股分红字段映射不全，Baostock补充 |
| **Tushare** | 前十大股东及持股比例 | **新增数据源**。用于管理层评估——是否为家族企业、创始人持股比例 |
| **SEC EDGAR** | 美股10-K年报：业务描述(Item1)、风险因素(Item1A)、MD&A(Item7) | 用于定性分析——了解公司做什么、风险在哪 |
| **Finnhub** | 公司新闻 + 内部人交易记录 | 判断市场情绪、管理层是否在买卖自家股票 |
| **FRED** | 10年期国债利率、CPI、失业率、GDP | 用于计算 WACC（资本成本） |

### 代码格式

| 市场 | 格式 | 示例 |
|------|------|------|
| A股（深交所） | `xxxxxx.SZ` | `002327.SZ` |
| A股（上交所） | `xxxxxx.SS` | `600519.SS` |
| 美股（纳斯达克） | 代码 | `AAPL`、`XNET`、`DUOL` |
| 港股 | ❌ 暂不支持 | — |

### 输出

产出 `out/temp_data/financials_[代码].json`，包含：5年利润表/BS/CF + 公司信息 + 派生指标 + 各数据源补充数据。

## 第2层：8个分析脚本（算了什么）

由 `financial-analysis` skill 的 9 个 Python 脚本完成。每个脚本读取第1步产出的 JSON，计算特定指标后输出到 `out/temp_data/`。

| 脚本 | 计算内容 | 用在报告的哪里 |
|------|---------|-------------|
| `calculate_reproduction_value.py` | **ARV — 资产重置价值**：现金×100% + 应收×85% + 存货×80% + PP&E×150% + 商誉×0% | 第5节：格林沃尔德三要素 |
| `extract_maintenance_capex.py` | **维护性CapEx vs 增长性CapEx**：从10-K提取，或从D&A比例估算 | 第5节：EPV调整、FV再投资率 |
| `analyze_roic_wacc_spread.py` | **ROIC-WACC 差值**：NOPAT/投入资本 vs 国债+Beta×ERP | 第2节：护城河判定 |
| `margin_decomposition.py` | **利润率逐层分解**：GP→OP→NI，5年趋势+利润质量评分 | 第4节：财务体检 |
| `audit_capital_allocation.py` | **资本配置审计**：回购/分红/SBC/并购效率评分(A-F) | 第3节：管理层评估 |
| `insider_alignment_check.py` | **内部人一致性**：持股比例+SBC+Finnhub交易记录 | 第3节：管理层诚信 |
| `detect_accounting_anomalies.py` | **会计异常检测**：DSO天数/存货周转/商誉占比/OCF-NI背离 | 第4节：财务体检 |
| `stress_test_margin_of_safety.py` | **4种情景压力测试**：基准/保守/悲观/极端下的ARV+EPV+FV | 第6节：下行风险 |
| `cross_validate.py` | **8项数据交叉校验（安全阀）**：检查现金/币种/ROIC/资产负债表/利润质量/估值顺序/债务/SBC | **强制校验，exit 2则暂停** |

## 第2.5层：交叉校验（为什么是安全阀）

`cross_validate.py` 在报告生成前执行 8 项检查，防止数据错误进入报告：

| 检查 | 检查内容 | 发现哪些问题 |
|------|---------|-----------|
| C1 | 非活期现金占比 | 短期理财是否过多（BZ 的¥158亿教训） |
| C2 | 币种一致性 | 净现金/市值 > 80% 时触发（ADR币种混用） |
| C3 | ROIC合理性 | >200% 或 <-50%（分母扭曲） |
| C4 | 资产负债表完整性 | 分项合计 ≠ Total Assets |
| C5 | 利润质量 | OCF/NI < 0.5x 或 SBC/NI > 50% |
| C6 | 估值顺序 | PB < 0.5x（市场认为资产质量差） |
| C7 | 债务安全性 | 负债率 > 70% |
| C8 | SBC稀释 | SBC/OCF > 30% |

**exit code 2 = 有错误 → 暂停报告生成，需人工修复。**

## 第3层：AI 生成投资报告

**估值前强制加载方法论文档对照。** 三模型各自独立计算，不求和、不合并。

### 三种估值模型

#### 模型A：格林沃尔德三要素（主模型）

| 要素 | 含义 | 判据 |
|------|------|------|
| **ARV** 资产重置价值 | 把公司资产逐项重估后得到的地板价 | 市价 < ARV → 一级安全边际 |
| **EPV** 收益能力价值 | 假设零增长，当前盈利能力的现值 | 市价 < EPV → 二级安全边际 |
| **预期收益率** | 仅当 EPV > ARV 时计算 | 回报 > 资本成本 → 三级安全边际 |

#### 模型B：麦肯锡价值驱动模型

$$Value = \frac{NOPLAT \times (1 - g/ROIC)}{WACC - g}$$

内置自检：若 IR ≥ 1（g > ROIC），增长在销毁价值，退化为零增长模型。

#### 模型C：反向DCF

从市价反推市场隐含的增长率假设，与历史实际增速对比——验证市场是否过度乐观/悲观。

### 4 份报告

| 报告 | 内容 | 字数 | 视角 |
|------|------|------|------|
| **投资备忘录** | 9 板块完整分析 + 决策建议 | 2500-3500字 | 资深对冲基金分析师 + CFO |
| **思考链** | 数据溯源 + 计算步骤 + 假设验证 | 1200-2000字 | 技术型研究员 |
| **批判性审视** | 对抗式审查：假设压力测试 + 认知偏差 + 遗漏风险 | 1500-2500字 | 30年CFO + 首席风险官 |
| **巴菲特视角** | 8问快速过滤器 + 所有者收益 + 商业质量 | 1500-2000字 | 巴菲特/芒格思维 |

### 投资备忘录的 9 个板块

| 板块 | 内容 |
|------|------|
| **第1节：核心结论** | 一句话结论 + 市场共识(含Price Target) + 预期差(3项具体差异) |
| **第2节：商业模式** | 业务本质 + 多业务分拆表 + 业务痛点 + 单经济模型 + 护城河压力测试 |
| **第3节：管理层** | 三维评分(诚信/资本配置/所有者思维) + 股东收益率 + SBC稀释趋势表 |
| **第4节：财务体检** | 3年对比表 + 核心洞察(改善/恶化/矛盾) + 资产质量解剖 |
| **第5节：三模型估值** | 5a ARV(3年对比) + 5b EPV(7步+WACC敏感性) + 5c护城河验证 + 5d格林沃尔德判据 + 5e麦肯锡 + 5f反向DCF + 5g对比表 |
| **第6节：下行风险** | 3-5项风险(每项含触发条件+量化影响+历史参考+管理层应对) + 最可能伤害股价的情景 |
| **第7节：催化剂** | 4项左右潜在事件(可能性+影响+预期时间) |
| **第8节：三维扫描** | 质量/估值/催化剂 各0-10分(含理由) + 加权综合分 |
| **第9节：决策建议** | 操作建议 + 目标价 + 持有期限 + 买入逻辑 + 卖出条件 + 强制止损 |

## 第4层：Notion 上传

由 `notion-upload` skill 负责。上传到 **Report for Hermes** 页面：

1. 在父页面底部插入批次分隔标记：📌 `▶ [代码] — [日期] V[版本]`
2. 以子页面形式创建报告（默认在底部，Notion API 限制）
3. 页面标题含 emoji 前缀：📊 投资备忘录 / 🔍 思考链 / ⚠️ 批判性审视 / 🦅 巴菲特视角

```bash
cd ~/.hermes/skills/data-science/notion-upload/scripts
export $(grep NOTION_API_KEY ~/.hermes/.env)
python3 upload_to_notion.py --ticker [代码]
# 或指定文件：--files "file1.md,file2.md"
```

### 版本管理

| 规则 | 说明 |
|------|------|
| V1 | 每天对该股票的第一份分析 |
| V2+ | 同一天每重新生成一次 +1 |
| 跨天 | 重置回 V1 |
| 一致性 | 4 份报告使用同一版本号 |

## 注意事项速查

| 场景 | 注意 |
|------|------|
| **A 股** | 代码加 `.SZ` 或 `.SS` 后缀 |
| **中国 ADR** | yfinance 返回 CNY 财报 + USD 股价 → 统一币种 ×7.3 |
| **美股** | 自动获取 SEC 10-K + Finnhub 新闻/内幕 |
| **计算纪律** | 🚫 禁止脑算，所有估值必须用 Python |
| **数字格式** | 每条数字带币种前缀（¥/$）和单位（亿） |
| **估值纪律** | 三模型**独立**，不求和、不合并 |
| **SBC 处理** | 计算真实 FCF 时必须扣除 SBC |
| **交叉校验** | exit code 2 必须暂停，不可跳过 |
