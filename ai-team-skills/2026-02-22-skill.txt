● 根据代码库分析，这个项目包含 3 个核心 skill：

  📋 Skills 功能总览

  1️⃣ ai-team - 多 Agent 协作流水线

  命令: /ai-team 或 /team

  功能: 编排 Claude (Team Lead) + Codex Worker (代码) + Gemini Worker (UI) 的多
  Agent 协作

  核心能力:
  - 任务自动拆分与分配
  - 并行/串行流水线执行
  - 支持 3 种流水线模式：
    - 模式 A: UI 设计 → 审查 → 实现（串行）
    - 模式 B: 代码审查 → 确认 → 修复（串行）
    - 模式 C: 多模块并行开发 → 整合

  适用场景: 全栈功能开发、大型重构、UI+后端联动任务

  ---
  2️⃣ codex-agent - 代码编写与审查专家

  命令: /codex-agent 或 /codex

  功能: 委派代码任务给 Codex (gpt-5.3-codex, reasoning: high)

  核心能力:
  - exec 模式: 代码编写、修复、重构、测试
  - review 模式: 代码审查（支持审查未提交变更或分支差异）
  - 3 种沙箱模式：
    - full-auto: 标准权限
    - dangerous: 完整权限（可安装依赖、运行测试）
    - read-only: 只读（用于审查）

  跨平台: 提供 Bash (Linux/macOS) 和 PowerShell (Windows) 脚本

  ---
  3️⃣ gemini-agent - UI 设计与前端开发专家

  命令: /gemini-agent 或 /design-ui

  功能: 委派 UI/前端任务给 Gemini (gemini-3-pro-preview)

  核心能力:
  - UI 组件设计（表单、导航、模态框等）
  - 页面布局与响应式设计
  - 样式美化与视觉优化
  - 强调可访问性（ARIA、键盘导航）

  跨平台: 提供 Bash 和 PowerShell 脚本

  🎯 推荐使用策略

  如果你只需要简单调用

  直接用 CLI - 适合你已经熟悉参数的情况：
  codex exec --full-auto -C ./project - < prompt.txt
  gemini yolo "设计一个登录表单"

  如果你需要以下功能

  使用 Skill 包装 - 适合以下场景：
  1. 跨平台项目（需要同时支持 Linux/macOS/Windows）
  2. 复杂参数配置（review 模式、多种沙箱、超时控制）
  3. 流水线集成（多 Agent 协作）
  4. 团队协作（统一规范、prompt 模板）

  ai-team 是必须的吗？

  不是必须，但它提供了多 Agent 编排能力：

  💡 结论

  简单答案：可以只用 CLI，但：

  - Codex/Gemini CLI → 核心引擎（必须的）
  - codex-agent/gemini-agent → 便利包装（提升体验，可选）
  - ai-team → 编排系统（复杂任务才需要）

  类比：
  - CLI = 原始工具（锤子、锯子）
  - Skill 包装 = 电动工具（电钻、电锯）
  - ai-team = 自动化工厂（流水线）

  如果你只是偶尔用，直接 CLI 完全够用。如果你频繁使用或需要团队协作，Skill
  系统会节省大量时间。
